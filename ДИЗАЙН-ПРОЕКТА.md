# МатОлимп — Duolingo для олимпиадной математики

Дизайн-документ MVP. Дата: 2026-07-09.

---

## 1. Концепция и границы MVP

**Идея:** тренажёр по олимпиадной математике с упором на *темы*, а не абстрактную логику.
Структура обучения:

```
Курс
 └─ Тема (большая) ── основная теория темы
     └─ Подтема ── короткая теория подтемы
         └─ Задача ── условие + числовой/короткий ответ + эталонное решение
```

**Два типа задач (гибридная модель):**
- **Закрытые (короткие):** числовой/короткий ответ → **авто-проверка**, 3 попытки, честный XP. Ядро MVP.
- **Открытые (большие):** ученик пишет решение → сдаёт → **самопроверка по эталону** + **AI-фидбэк**, но балл ставится мягче (XP за факт попытки/самооценку, без жёсткой оценки доказательства).

Почему так: полноценно проверять доказательство AI не умеет и может засудить правильное решение. Мягкий режим убирает этот риск, но сохраняет пользу — ученик пишет, сравнивает с эталоном, получает разбор.

**Что входит в MVP (v1):**
- Первая большая тема — бесплатно; остальной курс — 500 ₽.
- Закрытые задачи: авто-проверка, **3 попытки**, потом блокировка.
- Открытые задачи: ввод решения → эталон + AI-фидбэк (мягкий балл).
- AI-объяснение эталонного решения по кнопке (DeepSeek).
- Геймификация: серия (streak), XP/баллы, уровни.
- Регистрация: класс + опыт в олимпиадах.
- Публикация в RuStore, оплата через RuStore Billing.

**Что НЕ входит в MVP (отложено на v2+):**
- AI-проверка полных доказательств (дорого, рискованно — сначала числовые ответы).
- iOS / App Store (сложно и дорого для старта).
- Синхронизация прогресса между устройствами через сервер (в MVP прогресс локальный).
- Соцфичи (рейтинги, друзья, лиги).

## 2. Технологический стек (обоснование под «не греется / не тормозит»)

| Слой | Выбор | Почему |
|------|-------|--------|
| Язык / UI | **Kotlin + Jetpack Compose** | Нативно, минимум оверхеда, нет прослойки как во Flutter/RN. |
| Формулы | **JLaTeXMath (ru.noties:jlatexmath-android)** | Рендер LaTeX **на Canvas**, БЕЗ WebView. WebView — главный источник тормозов/нагрева. |
| Локальная БД | **Room (SQLite)** | Контент и прогресс офлайн, мгновенный доступ, нет сети в горячем пути. |
| Архитектура | **MVVM + Repository**, однонаправленный поток (UDF) | Стандарт Android, тестируемо, предсказуемо. |
| Асинхронность | **Coroutines + Flow** | Не блокирует UI, экономит батарею. |
| DI | **Hilt** | Простая сборка зависимостей. |
| Навигация | **Navigation Compose** | Единый граф экранов. |
| Оплата | **RuStore Billing SDK** | Требование площадки. |
| AI-прокси | лёгкая serverless-функция (Cloudflare Workers / маленький VPS) | Прячет API-ключ DeepSeek, кэширует объяснения. |

**Ключевые правила производительности:**
1. Никакого WebView в горячих экранах — формулы только JLaTeXMath.
2. Тяжёлые формулы кэшировать как отрендеренный bitmap (LRU-кэш), чтобы не рендерить повторно при скролле.
3. Весь контент — локально в Room, сеть только для AI-объяснения и оплаты.
4. Списки через `LazyColumn` с ключами, без пересборок.

## 3. Модель данных (Room)

```
Course(id, title, description, price, isFree, order)
Theme(id, courseId, title, theoryMarkdown, order)
Subtheme(id, themeId, title, theoryMarkdown, order)
Problem(
  id, subthemeId, order,
  kind,                     // CLOSED (числовой ответ) | OPEN (пишет решение)
  statementMarkdown,        // условие с LaTeX
  answerSpec,               // JSON: тип ответа + правила проверки (см. §5); только для CLOSED
  referenceSolutionMarkdown,// эталон (для показа и для AI)
  difficulty                // 1..5
)

// Прогресс пользователя (локально)
UserProgress(problemId, attemptsUsed, status, solvedAtAttempt, earnedXp, draftSolution, selfAssessment)
  status ∈ {NOT_STARTED, IN_PROGRESS, SOLVED, LOCKED, SUBMITTED}
  // draftSolution/selfAssessment — только для OPEN-задач
UserProfile(name, grade, olympiadExperience, totalXp, level, streakDays, lastActiveDate)
Purchase(courseId, purchasedAt, receipt)   // факт покупки
AiExplanationCache(problemId, text)         // чтобы не дёргать AI повторно
```

Контент (курсы/темы/задачи) поставляется как **JSON-пакеты**, которые при первом запуске загружаются в Room (seed). Бесплатная тема — в APK; платный курс — можно доложить после покупки.

## 4. Экраны и навигация

```
[Онбординг/Регистрация] → спрашиваем: имя, класс, опыт в олимпиадах
        ↓
[Главная / Карта курса]  → список тем (как «дорожка» уровней Duolingo),
        │                   видны XP, серия, уровень
        ↓
[Экран темы] → основная теория темы + список подтем
        ↓
[Экран подтемы] → короткая теория + список задач (замок, если не куплено)
        ↓
[Экран задачи — ЗАКРЫТАЯ] → условие (LaTeX) → поле ввода ответа
        │        → «Проверить» (осталось N попыток)
        │        → верно: +XP, анимация, дальше
        │        → неверно: подсказка «попробуй ещё», -1 попытка
        │        → 0 попыток: задача заблокирована, доступны:
        │             • «Показать решение» (эталон)
        │             • «Объяснить решение» (AI)
[Экран задачи — ОТКРЫТАЯ] → условие (LaTeX) → большое поле для решения
        │        → «Сдать» → показываем эталон рядом
        │        → «Объяснить решение» (AI-фидбэк по эталону)
        │        → самооценка: «решил / частично / не решил» → мягкий XP
        ↓
[Профиль] → класс, опыт, статистика: XP, уровень, серия, % решённых
[Экран покупки] → разблокировать курс за 500 ₽ (RuStore Billing)
```

## 5. Логика проверки ответа (ядро)

Это про **закрытые** задачи. Открытые (§5.1) проверяются самооценкой + AI-фидбэком.

Математический ответ надо сравнивать **канонически**, а не строкой: `1/2` == `0.5` == `0,5`.

`answerSpec` (JSON у каждой задачи) задаёт тип и правила:

```json
{
  "type": "INTEGER | RATIONAL | DECIMAL | EXPRESSION | SET | STRING",
  "accepted": ["1/2", "0.5"],        // допустимые эталоны
  "tolerance": 1e-9,                  // для DECIMAL
  "orderMatters": false,             // для SET/списка
  "caseSensitive": false             // для STRING
}
```

Пайплайн проверки:
1. Нормализация ввода: убрать пробелы, `,`→`.`, привести дроби к общему виду.
2. По типу: INTEGER/RATIONAL — точное сравнение; DECIMAL — с `tolerance`; SET — сравнение множеств; EXPRESSION — упрощение (для MVP лучше свести к числу/канону, полноценный CAS не тащим).
3. Сравнить с каждым из `accepted`; совпало → верно.

**Правило попыток (закрытые):**
- `attemptsUsed++` при каждой проверке.
- Верно → `SOLVED`, начисляем XP (см. §6), задача закрывается со «звёздами».
- 3 неверных → `LOCKED`: XP не даём, открываем эталон + кнопку AI-объяснения.
- (v2) режим «повторить позже» для закрытых задач без XP.

### 5.1. Открытые задачи (гибрид)
- Ученик пишет решение в текстовое поле (сохраняем черновик).
- «Сдать» → показываем эталон и кнопку AI-фидбэка (AI сравнивает с эталоном и даёт разбор: что верно, чего не хватает; **без вердикта-балла**).
- **Самооценка** ученика: «решил / частично / не решил» → мягкий XP (см. §6). Честность — на совести ученика; это тренажёр, а не экзамен.
- Статусы упрощены: `SUBMITTED` вместо жёстких попыток.

## 6. Геймификация (конкретные формулы)

**XP за задачу** (зависит от попытки и сложности):
```
базаXP = {1-я попытка: 10, 2-я: 6, 3-я: 3}
XP = базаXP + (difficulty − 1) * 2
```

**XP за открытую задачу** (мягкий режим, по самооценке):
```
решил: 8, частично: 4, не решил (но попробовал): 1
```
Меньше, чем максимум за закрытую с 1-й попытки — чтобы самооценку нельзя было «фармить».

**Серия (streak):** решил ≥1 задачу за день → серия +1; пропустил день → серия сбрасывается.
Показывать «🔥 N дней». (v2 — «заморозка серии» как платный/наградной бонус.)

**Уровни:** `уровень = 1 + totalXp / 100` (каждые 100 XP — новый уровень). Прогресс-бар на главной.

**Визуальная награда:** анимация при решении, «звёзды» за задачу (3★ — с 1-й попытки, 2★ — со 2-й, 1★ — с 3-й).

## 7. AI-объяснение (архитектура и безопасность)

Нельзя звать DeepSeek напрямую из приложения — утечёт API-ключ. Схема:

```
Приложение ──► AI-прокси (наш сервер) ──► DeepSeek API
   │                 │
   │                 └─ ключ хранится ТОЛЬКО тут, + rate-limit + кэш
   └─ если объяснение уже в AiExplanationCache — не ходим в сеть
```

Прокси: одна лёгкая функция (Cloudflare Workers — бесплатно и работает в РФ, либо дешёвый VPS timeweb/selectel).
Промпт: «Вот условие задачи и эталонное решение. Объясни решение школьнику класса {grade} пошагово, простыми словами, не меняя математику эталона.»
Экономия: кэшируем ответ по `problemId` (объяснение одно и то же для всех) → почти нулевая стоимость на масштабе.

## 8. Монетизация

- 500 ₽: разблокировка курса (RuStore Billing, `purchaseProduct`).

## 9. Контент: пайплайн и юридический момент

**⚠️ Важно:** нельзя напрямую копировать теорию и авторские решения с matsfera.ru в платный продукт — это нарушение авторских прав и повод для жалобы в RuStore.
- matsfera — источник **структуры и вдохновения** (какие темы, в каком порядке).
- Теорию и разборы **пишешь/переформулируешь сам** (ты эксперт — это твоё преимущество).
- Условия классических олимпиадных задач использовать проще (сами задачи с известных олимпиад), но авторские решения — свои.

**Формат авторинга:** таблица/Google-таблица или Markdown → скрипт-конвертер → JSON-пакет курса → seed в Room. Так ты добавляешь контент, не трогая код.

## 11. Дорожная карта (по фазам)

**Фаза 0 — окружение (перед кодом):**
Установить Android Studio + JDK, создать проект, подключить зависимости (Compose, Room, Hilt, JLaTeXMath). Понадобится физический Android-телефон или эмулятор для проверки.

**Фаза 1 — вертикальный срез (главное!):**
Одна тема → одна подтема → 3–5 задач, зашитых в JSON. Экран задачи с вводом, проверкой, 3 попытками и показом эталона. Рендер LaTeX. Без AI, без оплаты. Цель — пощупать главный цикл.

**Фаза 2 — геймификация и профиль:**
XP, уровни, серия, карта курса, регистрация (класс/опыт), статистика.

**Фаза 3 — AI-объяснение:**
Прокси + кнопка «объяснить» + кэш.

**Фаза 4 — монетизация:**
RuStore Billing, paywall, разблокировка курса.

**Фаза 5 — контент и релиз:**
Наполнить первую тему целиком + 1 платный курс, тест на реальном телефоне, публикация в RuStore.

## 12. Ориентировочные расходы

- Разработка: 0 ₽ (пишем сами).
- Публикация в RuStore: бесплатно.
- AI-прокси: Cloudflare Workers — бесплатный тариф; DeepSeek — копейки за счёт кэша.
- VPS (если выберем его вместо Workers): ~200–400 ₽/мес.
- Домен для прокси (опц.): ~200–900 ₽/год.

Итого старт — почти бесплатный; основная инвестиция — твоё время на контент.
```
